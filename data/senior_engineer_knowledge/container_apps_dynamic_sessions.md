# Senior Cloud Engineer Knowledge Base: Azure Container Apps Dynamic Sessions

Domain: serverless
Difficulty: senior
Applies to: Azure

## Overview
Azure Container Apps Dynamic Sessions provides fast, sandboxed, ephemeral execution environments designed for running untrusted code and executing AI agent workflows at enterprise scale. With sub-second container cold starts, Dynamic Sessions solves the challenge of safely executing arbitrary Python or custom container code generated by LLM agents. Each session runs in an isolated Hyper-V microVM container with strict network egress controls, file system virtualization, and automatic lifecycle teardown.

## Key Features
- **Sub-Second Cold Starts**: Instant session provisioning through warm container pooling, delivering initial response latency under 500 milliseconds.
- **MicroVM Hypervisor Isolation**: Each session is isolated using Microsoft Hyper-V hardware virtualization boundaries, preventing container breakout and host compromise.
- **Built-in Code Interpreter**: Pre-configured Python 3.11 execution runtime equipped with popular data science, machine learning, and visualization libraries (Pandas, NumPy, Matplotlib, SciPy).
- **Custom Container Sessions**: Execute custom containers (custom compilers, Node.js, C#, Go) within sandboxed microVMs.
- **Managed Session Lifecycle**: Configurable idle session expiration (e.g. 5–60 minutes) with automated cleanup and zero management overhead.

## Pricing
- **Session Active Compute**: Billed per session-second while executing code or held warm; ~$0.000024 per vCPU-second and ~$0.000003 per GiB-second.
- **Warm Pool Management**: Automatically managed by Azure Container Apps without baseline infrastructure reservation charges.

## Use Cases
- LLM Agent code interpreter tools (e.g. executing data science scripts and charts generated by LangChain, Semantic Kernel, or AutoGen).
- Safe evaluation of user-submitted code in developer coding interview and competition platforms.
- Multi-tenant software SaaS executing untrusted customer plugins, scripts, and transformations.

## Limitations
- **Ephemeral Storage**: All files, uploaded artifacts, and created directories are strictly ephemeral and destroyed when the session times out.
- **Outbound Network Lockdown**: By default, network egress is restricted to prevent malicious command-and-control (C2) callback; outbound web requests require explicit allow-list configuration.
- **Session Lifetime Maximum**: Individual sessions have a maximum continuous lifetime (typically 1 to 4 hours).

## CLI Examples
```bash
# Create a Dynamic Sessions session pool in Azure Container Apps
az containerapp sessionpool create \
    --name "agent-sandbox-pool" \
    --resource-group "rg-enterprise-ai" \
    --location "eastus2" \
    --container-type "PythonLTS" \
    --max-sessions 50 \
    --ready-sessions 5

# Execute python code in dynamic session via REST/CLI
az containerapp sessionpool execute \
    --name "agent-sandbox-pool" \
    --resource-group "rg-enterprise-ai" \
    --code "import pandas as pd; print(pd.__version__)"
```

## Terraform / IaC
```hcl
resource "azurerm_container_app_environment" "env" {
  name                = "ca-prod-environment"
  location            = "eastus2"
  resource_group_name = "rg-enterprise-ai"
}

resource "azapi_resource" "session_pool" {
  type      = "Microsoft.App/sessionPools@2024-02-02-preview"
  name      = "python-interpreter-pool"
  parent_id = azurerm_resource_group.rg.id
  location  = "eastus2"

  body = jsonencode({
    properties = {
      environmentId = azurerm_container_app_environment.env.id
      poolManagementType = "Dynamic"
      containerType      = "PythonLTS"
      scaleConfiguration = {
        maxConcurrentSessions = 100
        readySessionInstances = 10
      }
      dynamicPoolConfiguration = {
        executionType = "Timed"
        cooldownPeriodInSeconds = 300
      }
    }
  })
}
```
